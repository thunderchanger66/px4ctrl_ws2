# PX4Ctrl + EGO 速度与跟踪参数实验

## 目标与范围

在当前 MID-360 X500 SITL、FAST-LIO/PGO、EGO、`px4ctrl` 完整链路上，寻找安全约束下到达目标最快的配置，并同时降低 EGO 参考轨迹到 FAST-LIO 实际位置的跟踪误差。PX4、FAST-LIO/PGO 外参、坐标变换、障碍物膨胀和碰撞距离参数保持固定；参数试验先只调整 EGO 速度/加速度/jerk，再对优选 EGO 配置测试 px4ctrl 增益。

每轮使用相同工厂场景、同一起飞流程和目标，落地并确认 disarmed 后关闭 PX4/Gazebo、FAST-LIO/PGO、bringup 和诊断节点，再启动下一轮。参数只通过 launch override 或本目录的 px4ctrl 参数副本加载，不污染默认控制器配置。

## 当前实验入口

`bringup.launch.py` 新增可覆盖的 EGO 参数，默认值与修改前一致：

| Launch 参数 | 基线 | 用途 |
| --- | ---: | --- |
| `ego_max_vel` | `1.0 m/s` | EGO 速度上限 |
| `ego_max_acc` | `1.0 m/s^2` | EGO 单轴加速度可行性限制 |
| `ego_max_jerk` | `3.0 m/s^3` | EGO jerk 可行性限制 |
| `ego_lambda_smooth` | `2.0` | B-spline 平滑项权重 |
| `ego_planning_horizon` | `7.5 m` | 局部规划范围 |
| `ego_obstacle_inflation` | `0.45 m` | 障碍膨胀半径 |
| `ego_collision_clearance` | `0.65 m` | 优化器障碍清距 |

完整控制器 profile 副本位于 `profiles/`；它们只改 `kp/kv`，其余安全参数与 `px4ctrl_bringup.yaml` 相同。

## 指标定义

| 指标 | 计算方式 | 判定用途 |
| --- | --- | --- |
| 稳定到达时间 | 从 `/goal_pose` 时间戳到 FAST-LIO 位置误差 `<=0.20 m` 且速度 `<=0.20 m/s` 持续 `1.0 s` | 主优化目标，越小越好 |
| 3D 跟踪误差 RMSE / P95 / 最大值 | EGO `PositionCommand.position` 与同一 lidar frame 的 FAST-LIO odometry 位置之差 | 跟踪质量；需报告 RMSE 与 P95，避免均值掩盖尖峰 |
| 平面跟踪误差 RMSE | 上述误差的 XY 分量 | 水平轨迹精度 |
| 最终目标误差 | 稳定到达时 FAST-LIO 位置到目标的距离 | 目标精度 |
| 实际速度 P95 / 峰值 | FAST-LIO 世界速度向量范数 | 到达速度与动态负荷 |
| EGO 加速度峰值/jerk 峰值 | `/drone_0_planning/pos_cmd` 加速度及相邻样本差分 | 检查实际轨迹是否遵守配置、重规划是否有尖峰 |
| px4ctrl 饱和比例、倾角、推力 | `/px4ctrl/debug` 饱和标志、倾角和推力 | 控制余量；长时间饱和或接近倾角上限不接受 |
| 膨胀地图最近距离 | FAST-LIO lidar 位姿到 `/drone_0_grid/grid_map/occupancy_inflate` 最近占据体素中心的距离 | 避障余量代理指标；须注明它不是 Gazebo 接触传感器 |
| 地图新鲜度 | 膨胀占据图发布时间年龄 P95 | 确保障碍判断基于及时地图 |
| 完成/安全事件 | stable arrival、failsafe、Offboard、EGO odom 越界/超时、重规划失败、控制参考 blend 与降落状态 | 识别失败实验，不以“没有碰撞”单独判定成功 |

最终只从完成到达、PX4 未 failsafe、没有 EGO 里程计/地图错误、膨胀地图 clearance 达到门槛、控制饱和处于可接受范围的 profile 中选择最快者；如果到达时间相差不超过 5%，选择跟踪误差更低的 profile。未到达、任务链路中断或数据缺失的轮次标为无效，不参与参数排名。

## 安全与可比性门槛

- 每轮开始前由独立起飞脚本爬升 `0.5 m` 并等待稳定；再发送相同的 lidar-frame 自动 yaw 目标。正式参数对比目标设为 `(2.0, 0.0, 0.5) m`，若基线在该路线无法稳定到达，则先用已确认可到达的 `(1.0, 0.0, 0.5) m` 确定可行路线，再固定路线比较所有 profile。
- `obstacles_inflation=0.45 m`、`dist0=swarm_clearance=0.65 m` 在所有 profile 中固定；不通过缩小避障范围换速度。
- 暂定可接受条件：最小膨胀地图 clearance `>=0.50 m`、地图年龄 P95 `<=0.20 s`、控制饱和样本比例 `<5%`、峰值倾角 `<25 deg`、无 failsafe/Offboard 丢失/落地前重规划或里程计异常。若场景观测达不到基线条件，先处理链路或更换固定可行路线，不放宽条件。
- Gazebo GUI 关闭以减少渲染导致的实时因子变化；物理世界、PX4 参数、障碍物和运行顺序固定。保存每轮 CSV/JSON，并从 PX4 ULog/ROS 状态检查安全事件。

### B0 基线详情

首次原始记录：[`B0_baseline_2m.csv`](B0_baseline_2m.csv)、[`B0_baseline_2m.json`](B0_baseline_2m.json)；复测：[`B0_baseline_2m_repeat.csv`](B0_baseline_2m_repeat.csv) / JSON。达到条件为误差 `<=0.20 m`、速度 `<=0.20 m/s` 连续 `1 s`。两次时间 `7.430/7.730 s`，RMSE `0.180/0.180 m`，P95 `0.320/0.317 m`，终点误差 `0.042/0.053 m`。速度峰值 `1.237/1.230 m/s`，加速度范数峰值 `2.090/2.123 m/s^2`，膨胀图 clearance min `0.921/0.917 m`，无 failsafe、无 EGO odom 越界/超时、无控制饱和。首轮有一次 reset blend；复测无 reset blend。

### E2 提速详情

有效重复记录：[`E2_v14_a16_j5.csv`](E2_v14_a16_j5.csv)、[`E2_v14_a16_j5.json`](E2_v14_a16_j5.json)。E2 实际速度峰值 `1.644 m/s`、P95 `1.565 m/s`；命令加速度范数峰值 `1.757 m/s^2`、倾角峰值 `16.25 deg`。目标到达稳定后即冻结任务指标；随后由独立 land helper 确认 `landed=true`、`DISARMED`。第一次 E2 采样因 goal 事件监听漏收并把降落收尾混入日志而作废，未纳入排名。

### E3 / C1 详情

E3 原始记录为 [`E3_v16_a20_j6.csv`](E3_v16_a20_j6.csv) / JSON。此档达到后时间明显增加，速度峰值 `1.817 m/s`、加速度峰值 `4.404 m/s^2`，控制饱和约 `4.97%`；拒绝此速度档。

C1 原始记录为 [`C1_kp18_kv14.csv`](C1_kp18_kv14.csv) / JSON。相对 B0 的 RMSE 从 `0.180` 降至 `0.166 m`，P95 从 `0.320` 降至 `0.298 m`，最终误差维持约 `0.043 m`，膨胀图最近距离 `0.925 m`。到达时间增加 `0.187 s`（约 `2.5%`），故 C1 与 B0 均处于 Pareto 前沿：B0 更快，C1 跟踪更准。

C2 原始记录为 [`C2_kp20_kv15.csv`](C2_kp20_kv15.csv) / JSON。提高增益没有继续改善误差：RMSE `0.176 m`、P95 `0.330 m`、最小间距 `0.789 m`，均逊于 C1；到达 `7.619 s` 也没有速度收益。

C1 第二次记录为 [`C1_kp18_kv14_repeat.csv`](C1_kp18_kv14_repeat.csv) / JSON。两次结果差异较小，位置 RMSE 均约 `0.17 m`、P95 约 `0.30 m`，终点误差小于 `0.05 m`、最小膨胀图间距约 `0.92 m`，无 failsafe、无 ODOM 越界/超时、无 saturation。两次各记录一次加速度投影和一次到目标附近重规划。

## 推荐配置与结论

**主推荐（优先避障余量和跟踪精度）**：EGO 保持 `max_vel=1.0 m/s`、`max_acc=1.0 m/s^2`、`max_jerk=3.0 m/s^3`、`lambda_smooth=2.0`、膨胀 `0.45 m`、清距 `0.65 m`；px4ctrl 使用 C1 的 `kp=[1.8,1.8,2.1]`、`kv=[1.4,1.4,1.6]`。同一 2 m 路线重复结果显示约 `7.57 s` 到达，跟踪 RMSE 约 `0.17 m`，P95 约 `0.30 m`，最小膨胀地图间距约 `0.92 m`。C1 profile 当前只在实验目录，**尚未覆盖正式 bringup 配置**。

**最快且保守的已测规划器设置**：B0 EGO `1.0/1.0/3.0` 配默认 px4ctrl。E1 `1.2/1.3/4.0` 比 B0 平均快约 `2.5%`，但跟踪 P95 从约 `0.32` 增到 `0.46 m`，最近障碍间距从约 `0.92` 降到 `0.71 m`，并出现加速度投影；不符合“最快同时缩小误差”的联合目标。更高 E2/E3 误差进一步增至 `0.54/0.60 m`、障碍距离约 `0.65 m`，E3 到达时间反而更慢且饱和接近门槛，拒绝。

速度与跟踪误差存在 Pareto 权衡，单个参数组不能同时改善全部目标。短的 2 m 路线上 C1 是跟踪误差与障碍余量的较好折中，B0 稍快且余量更大。没有通过缩小障碍膨胀、清距或扩大 PX4 倾角/推力限制来换速度。

但补充的历史 4 m 目标路线 `(4,-4,0.5)` 虽成功到达，报告的膨胀占据图最近距离只有 **0.050 m**，远低于 `0.50 m` 安全门槛。该路线明确判为**避障安全失败**；不能把前述短路线调参结果推广为工厂全场景安全，也不能声称当前配置已满足长航线障碍余量要求。原始记录见 [`C1_long_goal_4m.csv`](C1_long_goal_4m.csv) / JSON。继续扩大速度档或把 C1 直接用于长航线前，必须先修复/验证局部占据图与点云膨胀余量，并在地图显示的障碍物前后做实景轨迹检查。这个失败结果保留在记录中，不能以短路线结果抵消。

**当前可执行建议**：对短的、已验证走廊，优先使用 B0 EGO 限值配 C1 px4ctrl 增益；若目标优先是最短时间，则使用 B0 默认增益。E1/E2/E3 都不作为推荐提速配置。对 `(4,-4,0.5)` 长路线，在 clearance 指标达标之前不批准速度优化结果为安全配置。

## 最终指标状态

| 要求 | 指标/门槛 | 结果 |
| --- | --- | --- |
| 快速到达 | 与 B0 到达时间比较 | E1 仅快约 `2.5%`，E2 约 `3.6%`，E3 慢约 `21.7%`；收益伴随明显跟踪误差或安全余量恶化 |
| 跟踪误差 | 短路线位置 RMSE `<=0.20 m`、P95 `<=0.35 m` | B0 RMSE 通过、P95 临界；C1 两次均通过；C2 P95 略未达 `0.35 m` |
| 避障地图余量 | inflated-map clearance min `>=0.50 m` | 短路线 B0/E1/E2/E3/C1/C2 均超过门槛；长路线 C1 为 `0.050 m`，失败 |
| 控制余量 | saturation `<5%`、tilt peak `<25 deg` | 短路线各有效轮次达到；E3 饱和 `4.97%`，贴近边界且不接受 |
| 状态稳定 | 无 failsafe、任务期间无 odom timeout/out-of-map/replan fail、稳定落地 | 有效短路线轮次满足；长路线安全门槛失败；每轮完成后确认 landed/disarmed |
| 重复性 | 至少两次同 profile | B0 与 C1 均有两次短路线复测，趋势一致 |

**总判定：短路线调参完成；全场景避障目标未通过。** 还需针对长路线附近障碍更新/核对地图观察质量和膨胀区，再重新完成长路线避障验证后，才能给出全任务安全结论。

## 操作记录

所有实验使用 `benchmark_observer.py` 记录。每轮用 `land_vehicle.py` 请求 `NAV_LAND`，并等待 PX4 disarm 和 land/near-ground 静止确认；当前 SITL land detector 有时不置 `landed=true`，这时落地工具会在 Gazebo 位姿接地、速度稳定后发送标准 disarm 请求并确认 DISARMED。随后关闭整套 PX4/Gazebo、PGO/FAST-LIO、bringup 和 observer，再启动下一轮。

正式复测命令示例（先按既有顺序启动 PX4/Gazebo、PGO 和 bringup，并确保配置组一致）：

```bash
python3 test/experiments/benchmark_observer.py \
  --csv test/experiments/2026-11-12_speed_tracking/repeat.csv \
  --goal-x 2 --goal-y 0 --goal-z 0.5
ros2 run px4ctrl takeoff --altitude 0.5 --wait-timeout 45
ros2 run px4ctrl manual_goal 2.0 0.0 0.5 --auto-yaw --wait-timeout 30
python3 test/experiments/land_vehicle.py --timeout 90
```
